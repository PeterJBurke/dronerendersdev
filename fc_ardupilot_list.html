Method: the board list is parsed from the wiki source of https://ardupilot.org/copter/docs/common-autopilots.html (common/source/docs/common-autopilots.rst, ardupilot_wiki commit ab8cc333d3), one row per list entry, grouped by the page's own sections. Each board is mapped to its hwdef directory in ardupilot commit 3d6ebedc38; MCU, UART count (UART/USART entries in SERIAL_ORDER, USB excluded) and the tunes column are produced by a script over the hwdef tree with include and undef followed. Connector cells are taken only from the text of the board's wiki page and hwdef README; pinout images were not read, and anything not stated in text is NOT CONFIRMED. "servo rail" in the text is counted as 2.54 mm headers. The stock sentence "you can attach an external compass using I2C on the SDA and SCL pads" counts as red (solder pads) unless the same page states plug-in connectors for all peripherals, in which case it is put in the Note. A few connector cells use a vendor or retailer page instead and say so in the cell or Note. Price and stock come from the vendor store first, otherwise a retailer page that could be fetched; nothing is from memory. Non-USD prices are as listed, not converted. "in stock" needs a stock count, an available flag, or a store that labels sold-out items and does not label this one; add-to-cart alone with no stock text is NOT CONFIRMED. Vendor country (in brackets after the vendor) is given only where a fetched page states it. Tunes spot-check by hand against hwdef.dat: BlitzWingH743 (PA15 ALARM via include of BlitzH743Pro), AET-H743-Basic (PA15 ALARM), MatekH743, Pixhawk6C, ARK_FPV, FlywooH743Pro, omnibusf4pro, LumenierLUXF765-NDAA (ALARM lines present); KakuteH7v2 (via include of KakuteH7), speedybeef4v4, MicoAir743v2, TBS_LUCID_H7, GEPRC_TAKER_H743 (BUZZER GPIO only); HEEWING-F405, DroneerF405, modalai_fc-v1 (ALARM/BUZZER lines commented out, so none). All matched the script.

Tunes rule (checked against libraries/AP_HAL/board/chibios.h, AP_HAL_ChibiOS/hwdef/scripts/chibios_hwdef.py, AP_Notify/ToneAlarm.cpp and https://ardupilot.org/copter/docs/common-buzzer.html): AP_NOTIFY_TONEALARM_ENABLED is on when the hwdef yields HAL_PWM_ALARM, which the hwdef script emits only for a timer pin tagged ALARM (e.g. PA15 TIM2_CH1 TIM2 GPIO(32) ALARM). yes = such a pin exists (passive piezo plays the ArduPilot tunes). beeps only = no ALARM timer pin, but a BUZZER GPIO / HAL_BUZZER_PIN (active buzzer, simple beeps). none = neither. Linux boards: yes only if the hwdef sets AP_NOTIFY_TONEALARM_ENABLED 1, beeps only if it sets HAL_BUZZER_PIN. Not counted per row: DroneCAN buzzers, DShot/BLHeli motor beeps (HAL_DSHOT_ALARM_ENABLED also compiles ToneAlarm in), and the wiki's custom-build route that plays tunes on a motor output (SERVOx_FUNCTION 138/139). The pin shown is the MCU pin, not the board label.
